# 任务与 GitHub Issue 同步

## 双层记录

- GitHub Issue：面向项目外部，记录用户问题、目标、优先级、讨论和关闭状态。
- `docs/tasks/`：面向项目内部，记录执行上下文、受影响文件、验收条件、风险和验证结果。

两者不复制整段内容，而是通过 Issue 编号关联。

## 生命周期

1. 创建功能、缺陷、迁移或部署 Issue。
2. 在 `backlog.md` 增加一行，附带 Issue 编号和验收条件。
3. 开始工作时移到 `active.md`，补充分支、关键文件和验证命令。
4. 合并/发布后移到 `done.md`，记录提交、验证和关闭的 Issue。

## 条目格式

```markdown
## <短标题>

- Issue: #123
- 状态: backlog | active | done
- 目标: <用户可见结果>
- 验收: <可观察的通过条件>
- 影响: <认证、D1、离线、UI、部署或无>
- 验证: <命令与浏览器流程>
```

微小的错别字或无行为变化的格式调整不需要 Issue；其余工作项必须建立关联。
